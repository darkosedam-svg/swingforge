Contract v1 — read before writing a broker, resolver or engine:
- `Broker.on_bar(bar, bar_index)` is called exactly once per closed 4H bar with `Context.bar_index`. An order is still live *on* its expiry bar and is dropped (no fill) when `bar_index > expires_at_bar`; `expires_at_bar is None` never expires. The engine sets `expires_at_bar = ctx.bar_index + signal.expires_in_bars`, `ctx.bar_index` being the bar the signal was emitted on.
- `Broker.submit` replaces on the key `(trade_id, leg)`; a `trade_id` of `None` never matches, so entry orders are always additive (across instruments too). It returns the id of the newly accepted order; a replaced order's id is no longer pending and `cancel` on it is a no-op.
- `ExitResolver.resolve` reports price levels only, at most two targets (`stop_after_partial` applies after `targets[0]`). The caller maps `ExitEvent.target_index` back to the pending `Order` and takes the `Fill.leg` label from it (Partial's first target → `leg="partial"`, the runner's → `leg="target"`). Time stops are `kind="market"` orders and never reach the resolver.
- `Context`: `bars()` is an O(1) read-only view, valid only until the next `push`; row 0 is not bar 0 after trimming, so translate with `offset_of(bar_index) -> int | None`. `snapshot() -> bytes` is the JSON producer for `Trade.context_snapshot`. `position` rejects a `Position` for another instrument. `max_bars` now defaults to `50_000`, so a 4-year 1H run never trims; ATR/ADX memoise incremental Wilder state per `(tf, n)`.
- `StaticSettingsReader` is truly static (read-only `settings` property). `InMemorySettingsReader(settings=None)` adds `set(settings)`, which bumps the version by 1 on every call — use it for WU-1B's "settings change applied at next bar" test.

Deviations (⚠ = directed by the orchestrator):
- ⚠ Dependency is `hyperliquid-python-sdk` (`import hyperliquid`); `hyperliquid-execution-toolkit` does not exist on PyPI.
- ⚠ `Order.kind` includes `"stop"`; `Order.trade_id`, `Fill.leg`, `Fill.trade_id` added; `core/settings.py` moved here from WU-1B; `web` may import `core`; `Broker.on_bar` is synchronous and returns fills in occurrence order.
- `Bar.ts_open` and `Fill.ts` reject naive datetimes and normalise any tz-aware offset to UTC; `Bar.subbars` must be same-instrument, a finer timeframe, inside the parent span and range, and oldest-first.
- `Context.adx()` returns NaN below `2n+1` bars (it is computable at `2n`; the stricter gate is the contract as specified) and 0.0 for a flat series; `atr()` is NaN below `n+1`. Only `Instrument.tick_size`, `Order.qty`, `Position.qty` and `Trade.risk_r` are constrained `> 0`; `Fill.qty` and `contract_multiplier` are finite-checked only, per spec §3.
- Extra files beyond the plan: `.python-version`, `.gitattributes` (LF), committed `uv.lock`, and `tests/unit/test_protocols.py` (stubs proving every protocol is implementable, plus the documented call sequence). Ruff excludes `docs/` (vendored reference code).

Contract v2 (orchestrator, after review): `ExitRule.initial_stop(signal, ctx) -> float` added (engine sizes against it; ATRFixedR returns its ATR stop, all other rules `signal.stop`); the engine assigns `trade_id` on the entry order too so the broker can attribute the entry fill to the trade (breakeven stop after a partial). `CONTRACT_VERSION = 2`, tag `contract-v2`.
