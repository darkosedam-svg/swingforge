# WU-1D — gate math + regime tagger

Built: `lab/gate.py` (normal tails, per-observation Sharpe, population moments, deflated Sharpe, Politis-Romano stationary bootstrap, drawdown/CAGR/MAR, the six-rule gate) and `lab/regime.py` (the six regime tags); 134 unit tests, 100% branch coverage on both modules. Gates: `uv run pytest -q` (221), `uv run lint-imports`, `uv run ruff check . && uv run ruff format .`, `uv run mypy swingforge`.

- `evaluate(config_r, baseline_r, bh_curve, *, years, n_trials=2016, min_trades=60, stressed_r=None, seed=0, trial_sr_variance=None) -> GateResult`. The three `*_r` are plain R multiples (P&L per unit of risk), one per closed OOS trade, **chronological** — the bootstrap's block structure assumes that order. `baseline_r` is the frequency-matched baseline to beat; `stressed_r` the same trades re-priced at 2x spread/slippage and 1.5x funding (omit it and rule 6 is `None`). `bh_curve` is a buy-and-hold equity curve for the same instrument and window, and `years` its span in calendar years — `years` feeds *both* MAR figures, so config and buy-and-hold must cover the same span. `n_trials` is the size of the search (2,016 configs), `min_trades` the rule-1 floor, `seed` makes every bootstrap reproducible.
- Rules: 1 `n >= min_trades`, and it **short-circuits** — below the floor rules 2-6 are `None`, not `False`; 2 `dsr.prob >= 0.95`; 3 bootstrap p5 of expectancy > 0; 4 bootstrap p5 of (config − baseline) > 0, ⚠ an *empty* `baseline_r` scoring `False` rather than being skipped; 5 `mar_config > mar_bh`; 6 rules 1-5 re-run on `stressed_r`. Read `rule6` on the outer result, never `stressed.passed` (the nested result's own `rule6` is always `None`, so its `passed` is always `False`). `passed` is computed from the six; `rules()` returns them keyed for the report table.
- ⚠ DSR variance `V` defaults to `1/(T-1)`, the null variance of the Sharpe *estimator*; pass `trial_sr_variance` once the tournament has observed the actual spread of Sharpe ratios across its configs (a larger V deflates harder). Recipe: `trial_sr_variance = float(np.var([gate.sharpe(r) for r in all_trial_oos_r], ddof=1))` over *exactly* the trials that entered the search, on the same **per-observation** scale as `gate.sharpe` — ⚠ that default is an estimator variance, not the spread across a 14-instrument grid whose configs share instruments and signals, so it almost certainly **under**-deflates and leaves rule 2 too easy. Pass V, or write `None` explicitly into the results row so the report records that the default was used; a NaN or infinite V now raises instead of silently poisoning `sr_star`. Sharpe is **per-observation, never annualised** — a common sqrt(periods) factor cancels out of the DSR and only invites a wrong periods-per-year constant. `DSRResult.kurt` is **non-excess** (3.0 for a normal sample); T < 3 or a zero standard deviation gives `prob = 0.0`.
- ⚠ Bootstrap: `p=0.1` (mean block 10 trades) is a **recorded conservative choice**, not a fitted one — the tournament should check lag-1..5 autocorrelation of the pooled OOS R series and drop to `p=1.0` (i.i.d.) if there is none, since blocks only widen the interval. Rule 4 resamples its two arms **independently by design** (frequency-matched track records, not aligned pairs, and not even the same length — there is nothing to pair). Rules 3 and 4 **share** the config's resample means, so `result.boot_p5 == stationary_bootstrap_p5(config_r, seed=seed)` exactly — benign, but they are not independent tests of the same data; the gate demands both rather than combining their p-values.
- ⚠ `mar` with zero drawdown is `inf` when CAGR > 0 else `0.0`; `cagr` raises on `years <= 0`. Equity curves must be finite and strictly positive, and R multiples finite — NaN/inf raise rather than averaging away. `equity_curve_from_r(rs, *, risk_pct=0.01, start=1.0)` compounds `1 + risk_pct * r`, is one point longer than `rs`, and **raises `ValueError` naming the R multiple and its index** when a trade would take equity to <= 0 (-100R at 1% risk) — so **wrap every `evaluate` call per config** and turn that into a failed results row, not a lost run. Rule 5 compares strictly, so two curves that never drew down tie at `inf` and the tie goes to buy-and-hold.
- ⚠ `regime.tag(ctx, *, adx_threshold=25.0, vol_window=20, min_history=60)` returns one of the six `REGIMES`. Trend iff `ctx.adx("1d", 14) > adx_threshold` (strict; a NaN ADX — under 29 Daily bars — ranges). Vol tercile = ddof=1 std of the last `vol_window` Daily **log** returns, ranked against the expanding history of that same rolling-vol series over all retained Daily bars, so it is relative to this instrument's own past rather than a cross-market constant. Under `min_history` retained Daily bars it is `midvol`, as is a vol that never varied (the comparisons are strict); closes must be finite and strictly positive, since a `log` of anything else would silently return a confident `midvol`. Diagnostic only — it never gates or sizes a trade.
- Gotchas: `evaluate` recurses once for rule 6 with `stressed_r=None`, so the nested result never nests further. `stationary_bootstrap_p5` takes a `statistic` (default `np.mean`); `bootstrap_difference_p5` resamples the two arms *independently* from one seeded generator. `GateResult` carries `baseline_n` (0 = no baseline trades, so rule 4's `False` is legible in the report) and `rules_1_to_5_passed` (read that, never `passed`, on a nested `stressed` result), and serialises an infinite MAR as JSON `Infinity` rather than `null`. `tag` reads `ctx.bars("1d")[:, 3]`, a view invalidated by the next `push`. No scipy: `norm_cdf` from `math.erfc` (not `1 + erf`, which cancels the far left tail away), `norm_ppf` from Acklam plus one Halley step — machine-precise at the tournament's `1 - 1/2016`, but ~1e-8 out at `p = 1 - 1e-12`; mirror through `-norm_ppf(1 - p)` if you ever need the far upper tail. Repo is LF — normalise if your editor writes CRLF.

Gotcha (orchestrator, after review): `GateResult.model_dump_json()` emits a bare `Infinity` for a zero-drawdown MAR, which is not RFC-8259 JSON; the results store and any API response must map it to a sentinel (e.g. the string `"inf"`) before persisting or serving.

**Post-plan change (2026-09-19): `effective_n`.** `deflated_sharpe` and `evaluate` take an optional `effective_n`, the number of independent observations behind a series whose trades are not independent draws (the tournament passes a universe trial's distinct entry days; see the WU-2C handoff). It replaces `n` only where `n` measures precision - the `sqrt(n - 1)` of the z-score and the default `V = 1/(n - 1)` - so a record cloned k times is as significant as the original; the Sharpe and the moments are still the series' own, rule 1 still counts trades, and the bootstraps still resample them. `None` (the default, and what every per-instrument trial gets) is the old behaviour exactly; values outside `1..n` raise, and fewer than three independent observations give `prob = 0`. `DSRResult.effective_n` records what was used.
