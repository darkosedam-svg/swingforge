# WU-1E — Store + Replay + PaperBroker

Built: `adapters/store.py` (DuckDB `Store`), `adapters/replay.py` (`ReplaySource`), `adapters/paper.py` (`PaperBroker`); 66 unit tests across `test_store.py`/`test_replay.py`/`test_paper.py`.

`ReplaySource.merged()`: 4H bars (with `subbars`) and Daily bars interleaved by close time, 4H first on a tie. Subbar attach is all-or-nothing (partial coverage → `subbars=()`) and now costs exactly 2 `Store.bars` calls per `history("4h")` (one 4H query, one 1H query for `[start, end+4h)`, bucketed by `_floor_to_4h`) instead of one 1H query per bar; attaching uses `Bar.model_validate` (not `model_copy`) so a malformed subbar raises `ValidationError` loudly.

`PaperBroker`: market fills at `bar.open`; limit at better-of(open, price). Exit legs resolve via `ExitResolver.resolve(stop_after_partial=entry_price if a partial is still pending)`, filled at the resolver's `event.price`. `submit` rejects `kind="stop"` entry orders (`NotImplementedError`). `_TradeState` tracks `filled_qty`, not `remaining_qty` directly — `remaining_qty = entry_qty - filled_qty` is a property; closing a trade sets `filled_qty = entry_qty` exactly (never a phantom float-dust residue) and pops the trade from `_trades`; `is_flat()` (`remaining <= entry_qty * 1e-9`, module const `_QTY_EPSILON`) gates `positions()`/carry-accrual — a cancelled (not filled) remainder still reports its real qty. Exit-fill cost is computed against the actual filled qty (`order.model_copy(update={"qty": qty})`), not the pending order's original qty. A pending target with no stop leg raises `RuntimeError` (engine invariant). `_fill_queue` is a bounded `collections.deque(maxlen=10_000)`, not `asyncio.Queue` (non-blocking `on_bar` can't tolerate `QueueFull`).

New primary keys (code-review pass): `orders(run_id, id)`, `fills(run_id, order_id, leg, ts)`, `equity(run_id, ts)`, `results(run_id, config_id, split)` — all writers now idempotent (`ON CONFLICT DO UPDATE`); pre-existing DBs without these PKs must be recreated. Bulk writers (`upsert_bars` etc.) build one numpy array per column and do one `INSERT ... SELECT ... FROM <registered relation> ON CONFLICT DO UPDATE` instead of `executemany` (~20 rows/s → 50k+ rows/s for a 10k-bar upsert) — nullable columns use a value+mask pair with `CASE WHEN mask THEN NULL ELSE value END`, since a numpy `object`-dtype array registers ~1000x slower here (no `pandas` installed). `write_settings` is transactional (`BEGIN`/rollback on error); `trades()` caches instrument lookups per distinct (venue, symbol).

Gotchas: DuckDB raises `ModuleNotFoundError: No module named 'pytz'` on native `TIMESTAMPTZ` — every timestamp is a naive `TIMESTAMP` UTC instant, tz reattached on read. `Decimal` fields round-trip as `VARCHAR`.

Gates green (`pytest` 153 passed incl. 2 `slow`, `ruff`, `mypy`, `lint-imports`); coverage store/replay/paper: 96% (replay 100%, store 98%, paper 93%; misses are unreachable-via-public-API defensive branches).

Follow-up fix (wu/1e-fills): `fills()` no longer busy-waits (`while True: await asyncio.sleep(0)`) — it awaits a lazily-created `asyncio.Event` that `on_bar` sets whenever it appends a fill; `close()` sets `_closed` and the event so `fills()` ends (after draining) instead of looping forever, and `log` is now bounded the same way as `_fill_queue` (`deque(maxlen=100_000)`, the store's `fills` table is the real audit trail). Gates green (`pytest` 441 passed, `ruff`, `mypy`, `lint-imports`).
